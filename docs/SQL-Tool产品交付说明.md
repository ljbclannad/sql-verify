# SQL Tool 能力说明

SQL Tool 帮助团队核对数据库迁移或替换后的 SQL 表现：整理业务系统访问数据库的语句，准备固定输入，再比较原库与目标库的实际结果。适用于 SQL 盘点、迁移前兼容性排查和已有用例的重复核对。

## 一轮核对会得到什么

| 环节 | 做什么 | 交付内容 |
| --- | --- | --- |
| 提取 | 从 MyBatis / MyBatis-Plus 项目收集 SQL，不启动完整业务应用 | SQL 模板、来源、条件变体及未提取原因 |
| 生成 | 使用明确参数或源库真实样本，选择代表场景 | 固定查询清单、受控写入用例和覆盖诊断 |
| 验证 | 在两库执行相同 SQL 和参数，比较结果 | 执行证据、差异及无法判定的原因 |
| 查看 | 按状态筛选并查看单条详情 | 可离线打开的 HTML 页面和 JSON 原始证据 |

这些环节可以一次串联，也可以分别运行，通过文件交接。已有固定清单时，无需重新接入业务源码。完整操作示例见[项目使用说明](../README.md)。

## 能帮助团队判断什么

查询比较能发现执行错误及实际数据差异，支持顺序比较或忽略顺序但保留重复记录次数。对分页、截断和空结果单独判断，避免把证据不足当作通过。

受控写入检查修改前数据、影响行数和修改后数据，随后回滚并核对相关记录是否恢复。它适用于支持范围内的单表 INSERT / UPDATE / DELETE；恢复未确认时停止后续写入。

来源记录帮助研发定位对应定义，覆盖报告说明本轮准备了哪些用例、哪些输入缺失，验证报告保留双侧执行证据。团队可以分别判断“收集完成”“场景准备完成”和“实际比较通过”。

## 使用前提和结论边界

两库需要事先准备可比较的数据与会话条件，工具不会同步数据。采样账号只用于源库读取；写入验证需使用指定的受控环境，并满足表、唯一键和事务要求。

| 看到的状态 | 可以说明什么 | 不能据此推断什么 |
| --- | --- | --- |
| 提取成功 | 得到了可用 SQL 结构 | 所有运行路径已收集 |
| 生成 COMPLETE / READY | 本轮规则和预算内已交付清单 | 所有参数组合已覆盖、两库已通过 |
| 查询 MATCH | 已确认范围内的结果一致 | 截断结果以外的数据也一致 |
| 写入用例通过 | 本次预期和回滚恢复检查通过 | 提交、跨库事务或外部副作用均已验证 |

工具不验证整个应用、Mapper 返回映射、提交阶段或正式性能指标。自增、序列和外部系统的变化不保证由回滚恢复。报告包含业务 SQL、参数和数据，需要按对应环境的访问范围保管。
