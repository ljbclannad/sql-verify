# 阶段三：验证清单生成与场景覆盖设计

文档类型：设计文档。

导航：[总体设计索引](./阶段方案索引.md) · 相关设计：[SQL 提取](./阶段一-SQL提取能力与独立工程.md) · [双库执行与比较](./阶段二-双库查询执行与对比方案.md)。

本文定义独立清单生成器的职责、输入充分性、场景选择、生成状态与覆盖边界。生成器以提取结果、明确参数及单源只读采样为依据，生成查询与受控 DML 用例；运行 SQL 捕获和 Mapper/API 覆盖作为扩展设计分别讨论。本文不承载开发任务、里程碑或实施进度，具体支持范围与使用方式见[生成器说明](../sql-manifest-generator/README.md)。

生成阶段通过文件与提取及验证阶段衔接，各工具保持独立。[统一入口](统一入口使用说明.md)负责传递本轮产物，生成器承担输入检查和状态判断。人工预算及简单配额不足按正常截断记录，真实错误继续影响 PARTIAL；生成完成不表示全覆盖或双库通过。

## 一、目标、项目边界与前置条件

目标是把离线提取结果转换为可重复、有代表性、能够交给现有验证器消费的验证输入：简单 SQL 按表控制数量、减少重复，XML SQL 优先补全条件结构与有效数据场景，并明确记录不能覆盖的部分。

```text
业务项目 → SQL 提取器 → 提取结果 ───────────┐
真实基准数据源＋生成配置 ──────────────────┤
                                         ↓
                              独立验证清单生成器
                                         ↓
                 queries.json / dml-cases.json＋覆盖诊断
                                         ↓
                            现有双库 SQL 验证器
                                         ↓
                               执行、比较与恢复报告
```

生成器归属 `sql-tool` 根工程的 `sql-manifest-generator` 子模块，纳入根工程构建和检查，保留自身配置、运行入口与发行包。它通过文件衔接已有工具，通过项目依赖复用共享契约；模板求值、SQL 解析及 JDBC 依赖由自身管理，不并入提取器、验证器或契约模块。

### 与 `sql-query-contract` 的工程依赖

`sql-query-contract` 负责查询与 DML 输入模型、JSON 读取及格式校验。生成器复用查询、参数、DML 用例模型及 `QueryManifestReader`、`DmlManifestReader`，契约不承担场景生成或数据库访问职责。

```text
sql-manifest-generator 模块 ──→ sql-query-contract
sql-extractor 模块 ───已有依赖──→ sql-query-contract
sql-verifier 模块 ────已有依赖──→ sql-query-contract
```

图中箭头表示工程依赖，前面的流程图表示文件输入输出。生成器不依赖提取器或验证器的实现 JAR，也不通过调用它们的内部实现完成生成。数据库采样、参数解析、按表去重、数量控制、XML 场景展开、清单写出和覆盖报告全部归属生成器；契约模块只承担共享输入模型与格式校验，不承接这些业务功能。

清单序列化归属生成器，按契约字段与编码规则写出后，使用契约读取器检查清单级错误、逐条诊断及内容一致性。依赖采用明确版本并随独立运行包交付；具体版本与获取方式由生成器说明维护。格式可读取不代表 SQL 已通过验证器范围检查或数据库执行。

生成器与其他模块共用根工程 Wrapper、JDK 和版本配置，由 Gradle 自动解析并构建契约项目依赖，不再通过外部契约 JAR 接入。源码示例的生成结果归属生成器 `build/`，交付包的生成结果归属包内 `reports/`，清单内容和状态规则不因输出位置改变。

| 工具 | 职责 | 边界 |
| --- | --- | --- |
| 提取器 | 扫描定义，输出模板、参数化 SQL、已有变体和诊断 | 保持离线能力，不新增数据库采样依赖 |
| 清单生成器 | 解析输入，读取元数据与真实数据，选择场景、固定参数、去重、生成清单和覆盖诊断 | 生成阶段只读数据库，不执行 DML，不承担双库比较、回滚或数据同步 |
| 验证器 | 消费固定 SQL 与参数，执行双侧查询或受控 DML，比较并报告 | 不新增场景展开、参数采样或自动推导回查逻辑 |

前置条件是现有查询及受控 DML 验证路径、清单契约和报告可用；指定测试环境、表范围和采样权限已明确。验证器默认两侧相关数据基线一致，结构与会话条件仍需满足执行要求；生成器不执行数据同步或基线核验，生成清单成功不代表两库比较通过。

基础范围不包括建表、写入测试数据、复制或同步两库数据、业务插件执行、复杂事务编排、成功提交和自动修复业务 SQL。缺失数据、绑定信息或验证器不支持的语法，应形成覆盖缺口。

## 二、输入、输出与契约衔接

### 输入

| 输入 | 用途与要求 |
| --- | --- |
| 提取输出目录 | 以 `sql.json` 中的定义 ID、来源、模板、参数化 SQL、条件变体及状态为输入，不读取 `errors.json` 和 `java-sql.json`；`all.sql` 和展示 SQL 仅供阅读 |
| 真实基准数据源配置 | 基础范围以 MySQL 基准源为采样来源；指定 catalog/schema、表范围和只读采样限制，密码使用环境变量或本地凭据引用 |
| 生成配置 | 简单用例数量、按表覆盖、采样范围与顺序、XML 场景上限、参数映射和人工场景 |
| 按需补充的只读资料 | 参数路径、类型、XML 依赖片段、人工映射；XML 恢复使用明确版本资源；需要业务类型或自定义转换的情形归入扩展类型上下文，不自动构建业务项目 |
| 可选基线记录 | 数据集标识、采样时间、环境与会话条件；未来可附加目标侧只读核对，基础范围不要求连接目标侧采样 |

MP 注入的动态模板、含已提取变体的 GENERATED 定义及明确引用 Wrapper 的模板不再重放，直接将顶层参数化 SQL 与各条件变体作为固定结构处理。结构去重后继续使用通用列映射与只读采样，逐结构记录提取位置、SQL 指纹和 `templateReplayed: false`；无可靠绑定、结构不安全或变体操作类型不一致时保留缺口，其他有效结构继续生成。普通动态 XML 的求值规则不变；显式固定参数只绑定顶层 SQL，不跨变体复用。场景与读取预算仍共用，固定结构验证不计为原模板触达或全部 Wrapper 组合覆盖。

当前提取输出尚未保存完整的类型化有序执行参数，不能假设仅凭 `sql.json` 即可无损重放。生成器须独立完成必要的参数路径解析、动态模板求值及支持的绑定转换；信息不足时通过显式映射或只读资料补齐，否则记录不可生成原因。生成链路不依赖提取器直接导出执行清单，也不要求为生成阶段修改提取器输出。

禁止从已填值展示 SQL 反推参数、按问号顺序猜测列映射，或把任意 Java 对象直接序列化为可执行参数。可确认的 SQL 列映射可自动解析，歧义、跨表关系、计算参数和业务 TypeHandler 必须有可靠转换依据。不支持的类型保留诊断，不强制转成字符串。允许人工为某个定义/变体显式提供逐位置的 JDBC 参数或采样列映射，但必须保留依据，不能把位置猜测称为自动解析。

### 提取输入的充分性边界

Wrapper 源码查询及受限更新场景按 GENERATED 定义的顶层 SQL 和变体接入固定结构采样。更新值由生成器配置或采样，必须核对完整定位键并只读推导前后预期；UPDATE 支持整组 WHERE 条件的一层外括号，不放宽 OR 或任意表达式。提取阶段的 `wrapperStrategy`、`wrapperSources` 说明场景是源码恢复还是空 Wrapper 基线；来源位置保存在提取产物中。生成器不重放 Wrapper，也不把参数采样成功解释为源码路径完整或业务运行参数已捕获。

提取文件提供定义身份、部分 SQL 结构和模板，但不足以普遍生成真实参数用例，也不能仅凭输出目录恢复全部 XML 条件与原始业务绑定行为。生成器消费这些文件，并为缺失信息接收显式配置和已有只读资料；无法补齐的定义保留缺口。

提取文件的接口依据包括 [ExtractedSql 模型](../sql-extractor/src/main/java/com/kairui/tools/sqlexport/model/ExtractedSql.java)、[XML 变体模型与展开逻辑](../sql-extractor/src/main/java/com/kairui/tools/sqlexport/template/XmlSqlExpander.java)、[文件写出逻辑](../sql-extractor/src/main/java/com/kairui/tools/sqlexport/output/SqlExportWriter.java)、[模板捕获逻辑](../sql-extractor/src/main/java/com/kairui/tools/sqlexport/template/SqlTemplateLanguageDriver.java)及[提取流程](../sql-extractor/src/main/java/com/kairui/tools/sqlexport/SqlExtractor.java)；本节约定消费边界，不要求改变这些源码。

| 信息 | 提取输入的接口边界 | 对生成器的影响与补齐方式 |
| --- | --- | --- |
| 定义身份与来源 | `id/sourceType/source/databaseId` 已有；`sourceType` 包括 XML、ANNOTATION、PROVIDER、GENERATED | 可建立目录与来源映射；GENERATED 不保证全部属于简单 MP，必须检查最终结构 |
| SQL 与模板 | `template/parameterizedSql/sql` 可有值，也可缺失；当前 `sql` 与 `parameterizedSql` 均保留 `?`，旧轮次可能含填值展示 SQL | 无参数的确定查询可沿用 SQL 结构；带参数 SQL 仍需解析模板或显式绑定资料，不能拆解旧展示值或从问号反推参数 |
| 条件变体 | `variants` 每条只有 `parameterizedSql/sql` | 普通 XML 仍重建求值或显式补充；MP 动态与 Wrapper 模板直接消费已展开的 `parameterizedSql` 及变体，按 SQL 列映射和真实样本恢复位置绑定，不按变体序号猜参数，不声称恢复原 Wrapper 路径 |
| 参数模式与原值 | 当前输出为 SAMPLE，不再使用历史参数模式驱动生成 | 参数由生成器显式场景或源库采样提供，不再导入 shared/sets 历史参数文件 |
| JDBC 绑定 | 未导出 `ParameterMapping`、实际绑定类型/值、`foreach/bind` 附加参数及 TypeHandler 配置 | 简单明确列条件可结合元数据和显式映射；复杂绑定需要生成器重建求值/绑定上下文，无法重建就不能输出可执行用例 |
| XML 上下文 | 只保存单语句模板；已注册语句可能保留预处理后的 include，失败/被替代定义可能仍含未展开引用 | 不等同于完整 mapper/configuration；按需提供引用片段、别名、参数类型及语言驱动设置，模板自足的语句不强制读取原工程 |
| 有效定义选择 | 保留 `databaseId`、状态与文字诊断，可能含被替代或未注册定义 | 缺少独立的有效定义选择快照；同名来源或 databaseId 冲突须明确选择源侧定义，两库执行同一 SQL，不分别选择各自方言版本 |
| 表与业务参数关系 | 未导出实际表身份、主键、唯一键、列类型、关系或参数别名规则 | 数据库元数据与 SQL 分析只补结构依据；`@Param`、`param1`、DTO、实体字段、关联与计算规则须通过显式资料确认 |
| DML 断言 | 未导出回查、原记录、后置预期、影响行数或键生成规则 | 必须只读采样加人工规则推导；这些信息不可能仅由参数化 SQL 自动得到 |
| 覆盖与错误 | 有状态、警告、`combinationsComplete` 及 `errors.json`，没有条件触达事件和原采样数据 | 读取有效定义自身的条目诊断，提取阶段错误由提取报告说明；有限候选域完成不能证明业务条件全覆盖 |
| Java 与运行行为 | `java-sql.json` 单独保存静态片段/Wrapper 原文；未捕获实际业务 Wrapper、插件改写及 Provider 全部路径 | 静态片段仅在提取结果中查看，生成器不读取或计入生成诊断；Provider 仅凭已提取固定结构及显式绑定处理，不调用业务 Provider 扩大路径 |

来源路径可能来自另一台机器，不保证本机可读。额外 XML/classpath 按显式资源映射定位，并记录内容指纹及与提取结果的匹配情况；不能直接信任 `source` 路径或用另一版本 XML 静默替换原定义。现有输出没有完整工程/依赖版本快照，只能比对已保存模板及调用方提供的版本依据，无法自动证明所有外部类型与原提取环境一致；无法确认时记录资料一致性缺口。辅助 `!selectKey` 语句单独标注，不把它当作普通 MP 查询凑配额，也不把它与 INSERT 编排为多步用例。

### 最小资料组合与补齐责任

| 场景 | 最小输入组合 | 补齐失败后的处理 |
| --- | --- | --- |
| 无参数确定查询 | 已选中的完整参数化查询 SQL、来源及真实绑定数为零的依据；按需核对查询范围 | 缺少完整 SQL、含模板或不属于现有查询子集则不导出；展示 SQL 没有问号不代表原语句无参数 |
| 简单带参数查询/DML | 参数化 SQL；模板中的明确路径或逐位置映射；元数据与固定样本；DML 另需定位及修改值规则 | 仅有 `?` 和展示 SQL 时不足，记录绑定缺口；DML 缺断言也不能导出 |
| 自足动态 XML | 完整模板、可确定的参数结构和别名、基准参数/映射、采样资料；生成器内的求值与绑定上下文 | 缺少元素类型、参数别名或求值能力时，只保留结构目录与诊断 |
| 依赖外部资料的 XML | 上述资料加同版本 XML 片段；业务类型与 TypeHandler 依赖按扩展类型上下文处理 | 不自动构建业务项目，不注册全部 Mapper；类、片段或配置不完整则标注不可重建 |
| Provider/仅固定变体 | 已提取的完整固定 SQL，加显式位置绑定或可确认列映射 | 只验证这个固定输入，不声称恢复 Provider 或动态定义的其他路径 |
| 真实 Wrapper/插件/动态表名 | 现有输出普遍不足；需要另行提供可信的最终 SQL 和已固定参数 | 留给后续运行捕获专项，基础范围不通过猜测或改写补全 |

`sql-query-contract` JAR 只提供清单模型与 JSON 校验，不提供提取输出适配器、MyBatis 模板求值、SQL 解析、参数采样或验证器范围检查。生成器可以在自身项目按需依赖标准 MyBatis、解析库和 JDBC 驱动，固定与资料匹配的版本；无需依赖提取器/验证器实现 JAR。基础输入通道使用固定 JDBC 参数或可确定的 Map/XML 场景，完整业务 classpath、类型别名和 TypeHandler 恢复属于扩展类型上下文；需要这些资料但无法恢复时保留缺口。生成阶段不启动 Spring、执行 Mapper、注册插件链或调用业务 Provider。

每条可执行用例必须具备四类证据：已明确选择且与原定义匹配的最终 SQL、可靠的有序类型化参数、场景与固定数据依据，以及符合现有下游子集的生成检查；DML 还须完整前后断言。缺失任一必需证据就不计入有效配额。额外资料由调用方提供，生成器负责解析、冻结与诊断；基础范围不要求提取器新增输出字段或验证器接受新字段。

### 输出

| 产物 | 内容与下游用途 |
| --- | --- |
| `queries.json` | 顶层 `queries`；每条仅 `id`、`sql`、可选 `parameters`，参数仅 `jdbcType/value`，沿用[查询示例](../examples/verifier/queries.basic.json)和[清单契约](../sql-query-contract/README.md) |
| `dml-cases.json` | 顶层 `cases`；每条沿用现有 `id/sql/parameters/expectedAffectedRows/probe`，回查含有序参数、`columnTypes`、`expectedBefore/expectedAfter`；见[DML 示例](../examples/verifier/dml-cases.design.json) |
| `coverage.json` | 生成器单独维护的定义与场景映射、表身份、去重合并来源、参数来源、条件路径、基线记录、数量统计、失败及未覆盖原因；不增加执行清单字段 |

上述文件名为约定。生成器不得覆盖提取结果；每轮使用独立输出目录。查询与 DML 分批交给验证器，使用现有配置分别指定 `queries` 或 `dmlCases`，不混装为一份查询清单。执行范围、比较规则和表权限继续由验证器配置管理，生成器只能提供建议，不替代人工基线核对。

执行 ID 由规范化结构和场景内容确定，来源映射另存；相同输入、配置和固定采样数据重复生成时，条目集合与 ID 应稳定。报告中保留生成条件，真实数据变化后不承诺重采样仍得到相同清单；回归重放使用已冻结的清单。

## 三、按表去重与可配置数量

### 简单 SQL 的分类和数量口径

简单 SQL 指能够可靠识别的单表、固定结构的基础增删改查，包括符合支持范围的简单 MyBatis-Plus CRUD。来源、结构及业务条件共同参与分类；无分组的单表基础 COUNT 可作为简单查询，带分组、多表关联、复杂 Wrapper 或不能确认的定义不自动归入简单类别。自定义注入器也按实际结构判断，不能仅凭 GENERATED 来源归类。

数量按“实际表身份 × 操作类别”累计，同表多个 Mapper 共享数量目标。表身份包含实际 catalog/schema/table，大小写与引用规则按数据库解析，不能仅凭表名后缀合并。`INSERT`、`UPDATE`、`DELETE` 默认各 3 条有效用例，三个值分别可配置；简单 `SELECT` 默认也为 3 条，另设独立配置。这里的数量是用例数，不是修改行数，也不是验证器的 `rows`。

数量控制接口结构如下，所有表统一使用同一组配额：

```json
{
  "simpleCaseCounts": {
    "insert": 3,
    "update": 3,
    "delete": 3,
    "select": 3
  },
  "maxXmlScenariosPerStatement": 10
}
```

数量接受非负整数；`0` 表示显式禁用对应简单类别，并记录为配置排除。未配置使用默认值，各表采用统一配额；非法数量及无法解析的表身份应明确报错。XML 场景上限另行管理，不受简单 SQL 的数量或禁用项影响。

数量是代表性用例的生成目标和上限，不保证无条件凑满。数据与支持范围足够时生成配置数量；不足时输出已有有效用例，并记录正常 QUOTA_SHORTFALL、目标数与实际数，不单独导致 PARTIAL。候选样本、无效参数及重复用例不计入有效数量，不复制相同用例凑数。

### 去重与代表性选择

1. 解析后规范化 SQL 结构，消除不影响语义的格式差异，保留投影列、写入列、条件、排序、分页和操作语义；不依赖简单字符串替换判等。
2. 对同表同类别的相同结构合并重复定义，保留全部 Mapper/statement 来源。相同表但不同结构仅属于同一数量池，不视为相同 SQL。
3. 在数量上限内优先选择不同有效结构和不同数据场景；结构少于目标数量时，再为已有结构选择不同代表性参数。相同结构、类型化参数及验证预期均相同的用例只保留一次。
4. 同表存在多于配额的不同简单结构时，按固定优先级选择并记录未入选结构及配额原因；不得将数量达标表述为全部定义覆盖。

简单 MP 查询依照相同规则汇总，不为不同 Mapper 的同类定义反复生成相同用例。列表、按键查询、计数等语义不同的结构保持区分；用例选择使用显式优先级；有可见唯一键时按键取样，无键时允许冻结有界只读前缀，并明确不保证重新取样时的顺序或样本。

按表配额只用于简单 SQL。XML 定义优先进入下一节的覆盖策略，包括结构简单的 XML 定义；跨来源共享完全相同的执行用例时仍保留 XML 来源和覆盖映射，不能因简单配额已满而跳过 XML 场景。

## 四、真实参数与 XML 覆盖策略

### 基准参数与真实数据

阶段一已有 `shared`、命名 `sets` 和 statement `values` 参数配置：有效配置的语句按明确输入生成一组结果；无有效配置的动态 XML 使用有限示例域展开。生成器保持这个提取行为，在自己的场景生成流程中补充真实参数与条件组合。

- 保留显式配置的基准参数，包括 `null` 和完整集合；提取输出中的示例值不能直接视为真实业务参数。
- 从一个基准数据源采样后固定参数，两库复用同一份输入，不分别采样不同记录。
- 采样保持单连接、单个只读事务与串行处理。成功的表身份解析按原引用缓存，可选 `excludedTables` 排除名单比较保留引号、大小写和完整 catalog/schema/table；不填或空数组不额外限制，非空时禁止列出的表；同一真实表的不同引用复用元数据，失败解析不缓存，缓存不跨运行共享。
- 主键、关联键、日期及过滤条件围绕同一关联业务记录采样；不能独立拼接互不相关的字段值，并将大量空结果视为有效覆盖。
- 参数路径到数据库列、关系和计算规则采用可验证解析结果或显式配置，不能仅凭名称推断。
- 每个场景使用独立参数对象；调整取值时记录原值来源、调整原因及对应条件，不污染原始场景。

基准场景与探索场景分别保存，场景求值不能补猜原参数、改变显式 null 或改写完整集合。求值与绑定归属生成器，`foreach/bind` 附加参数按最终 SQL 占位符顺序固定，当前提取器仅输出 SAMPLE，生成器不再提供 CONFIGURED 历史基准兼容处理。

查询采样保持最终业务 SQL、占位符数量及绑定顺序不变。真实空列值按元数据类型绑定为 null，不把等号条件改成 IS NULL，也不删改业务筛选。无主键或可见唯一键仍允许有界只读取样，标记顺序依据为 SOURCE_PREFIX；分页和受控 DML 的稳定范围与定位键要求保持独立。

聚合 WHERE 参数从原表真实记录采样，固定 WHERE/ON/HAVING 约束继续保留；需要聚合阈值时，通过允许 null 的分组键匹配实际分组，普通字段与 HAVING 聚合值来自同一组。辅助投影可以读取非分组参数列，最终业务 GROUP BY、投影和条件不改写。

### XML 优先覆盖范围

XML 不采用每表每类 3 条的配额，而以“定义 × 可达条件结构 × 代表性数据场景”为覆盖单位。已有模板用于重新求值，已有变体仅作为结构参考；再根据可靠参数补充代表性路径；依赖缺失或提取未保留的分支不得当作已覆盖。

| 覆盖维度 | 场景与要求 |
| --- | --- |
| 动态条件 | `if` 真/假、`choose/when/otherwise`、`where/set/trim`；优先覆盖每个可达分支，再补充有意义的组合，不强制开启逻辑冲突条件 |
| 集合与计算参数 | `foreach` 空、单元素、多元素，`bind` 的可确认求值；不能生成合法 SQL 的空集合路径记录缺口 |
| 有效数据 | 正常命中、明确无匹配、空值与空字符串、日期和数值边界；无匹配须有场景依据，意外为空不能算命中覆盖 |
| 关联、聚合与分页 | 关联键一致的样本、分组和重复数据、独立 count、首/中/末页及越界页；排序与比较范围有明确依据 |
| 特殊类型 | 数值精度、长文本及业务实际使用类型；现有契约不支持的 JSON、二进制或其他类型记录限制，不扩展验证器接口 |
| XML DML | 保留不同写入结构和条件路径，仅将现有验证器支持且可构造完整断言的用例放入 DML 清单 |

结构去重和数据场景去重分别处理。同一 SQL 结构可以保留命中、无匹配或边界等不同场景；相同执行输入可以合并，但所有对应的定义及条件路径必须可追溯。跨不同 XML 定义不能仅凭表名和操作类型丢弃业务差异。

### 上限与失败边界

配置 `maxXmlScenariosPerStatement` 默认 10，接受 1—4096 的整数，限制每个定义的最终有效场景数量；独立于提取器现有 `max-combinations`。候选求值次数、采样行数和查询超时另设有界限制，并在生成报告中保存实际值。有只读数据源时，在候选去重后、最终选择前探测最终查询，先选确认有业务数据的候选，再兼顾不同分支、结构与数据边界。COUNT 零值不算业务数据命中，未知或超限不视为空；成功确认源侧查询零行的候选不进入双库清单，保留原 SQL、类型化参数与 SOURCE_EMPTY 跳过证据。成功取样为空且无错误、限额或未观察结构时，定义标记 NO_EXECUTION_REQUIRED（无需执行 SQL）；仅含这种定义的生成可以 COMPLETE，但没有数据库验证通过结论。COUNT 返回数值零仍是一行结果，继续交付；失败、未检查和预算不足不当空数据处理。

达到人工上限记录正常截断；模板或参数映射缺失、复杂 OGNL、动态表名、`${}` 任意片段、驱动专属参数、业务插件改写以及验证器不支持的语法分别记录真实缺口。两类情况均保留具体定义、已覆盖范围和未覆盖原因，但不混用完成状态。有限候选展开不等于穷尽业务参数；不得以候选域完成或清单数量充足声称 XML 全覆盖。

## 五、受控 DML 用例生成

DML 执行与回滚继续属于[阶段二验证器](./阶段二-双库查询执行与对比方案.md#8-受控-dml-验证)；阶段三新增自动生成兼容用例的职责。生成器只读取元数据、现有记录和定位键占用情况，不通过试写产生预期结果，也不通过创建数据保证配额。

| 类型 | 参数、回查与预期的生成规则 |
| --- | --- |
| `INSERT` | 单表、显式列、单行 VALUES、固定未占用定位键；按配置规则使用真实字段样本并构造新键，核对已知约束；回查前为空，后为确定的写入值；不依赖生成键或不确定默认值 |
| `UPDATE` | 选择已有主键/完整唯一键记录，不修改定位键；生成可确定的新值，保存完整前置回查和预期后置值；同值或无匹配作为显式特殊场景 |
| `DELETE` | 选择已有主键/完整唯一键记录；保存前置回查，后置预期为空；无匹配仅作为显式特殊场景 |

每条必须生成有序类型化参数、同表显式列回查、`columnTypes`、完整 `expectedBefore/expectedAfter` 和预期影响行数 `0` 或 `1`。回查符合现有定位键与投影要求，包含定位键及所有显式写入字段；每个用例独立成立，不依赖上一个用例留下记录。

下游支持范围以现有 [DmlGuard](../sql-verifier/src/main/java/com/kairui/tools/sqlverify/dml/DmlGuard.java)、[DmlTableCheck](../sql-verifier/src/main/java/com/kairui/tools/sqlverify/dml/DmlTableCheck.java) 和 [QueryGuard](../sql-verifier/src/main/java/com/kairui/tools/sqlverify/query/QueryGuard.java) 为依据。契约读取器不会检查这些执行规则，生成器须独立实现保守的兼容检查，不能调用验证器内部类，也不能以 JSON 回读通过代替范围核对：

- DML 接受普通 ASCII 或反引号标识符、`?` 写入值及 AND 连接的等值定位；不接受注释。UPDATE 额外支持精确数值列的有符号 64 位整数固定赋值，以及 AND 连接的 `列 IS NOT NULL`、`列 != 整数`（或 `<>`）附加条件；除下述同列加一和受控 IN 外，不支持字符串/小数字面量、函数、其他计算表达式、OR 或其他批量写入。等值路径的完整定位键仍必须通过非空 `?` 参数确定，固定赋值不能修改定位键，回查必须覆盖固定赋值字段且不能附带业务过滤条件。自动填充函数或生成键仍不支持，不保证每表三类都能凑满。
- 生成器保留原 UPDATE 中的固定整数与附加条件，不把它们改写成另一条简化 SQL。自动候选先按原固定条件筛选再稳定采样；写入前后预期按实际列类型推导，匹配检查包含原附加条件，定位及恢复回查只保留完整键。自动场景仍只生成实际变化的一行；NULL 或已达目标状态等零影响场景须显式声明 expectedAffectedRows 为 0。带附加条件的只读采样和回查缓存与无条件版本隔离，条件值不同也不共用结果。
- 回查是同表显式列 SELECT，WHERE 恰好为完整定位键，定位参数与 DML 保持相同类型及非空值，不接受 `*`、别名或额外过滤。附加 DML 条件是否成立另行核对，不能把附加条件放进回查隐藏记录。
- INSERT 新键无占用不代表整行一定合法；所有已知唯一约束、必填列、外键和字段精度均须核对，未知默认值、约束或副作用记录缺口。源侧回查必须完整读取，失败/截断不能当作空集。
- DML 完整回查按真实表身份、投影列顺序、条件字段及参数的 JDBC 类型和值，在同一源侧只读事务内缓存。成功空集可复用，异常、截断、超时或预算超限不缓存；缓存结果只读且不跨运行共享。命中不重复计入查询次数和采样体积，新输入仍按现有预算读取，条件与唯一约束校验继续逐个候选进行。
- DML 环境要求 MySQL 协议下可确认为 InnoDB 的事务表，并拒绝可见触发器与外键级联。H2 夹具仅用于本地逻辑验证；源侧只读核对不能证明目标侧满足要求，具体 MySQL/YashanDB 驱动及环境仍由验证器预检与实际执行证据确认。

UPDATE 支持精确数值列的同列 `列 + 1`，以及 `CASE WHEN 列 IS NULL THEN 1 ELSE 列 + 1 END`；CASE 的判断列、加一列必须与赋值列一致，不扩展为任意表达式。多行 UPDATE 只接受完整单列主键/唯一键的非空参数化 `IN (?,...)`，不能混用其他 WHERE 条件，且不能修改任何主键或唯一键字段。IN 参数个数不得超过验证器 `rows`，回查必须使用同一字段及同顺序、同类型、同值的非空参数列表；重复参数保留 SQL 语义，只按实际记录计数。每例完整读取全部前置、后置和恢复行，仍串行执行、独立连接并无条件回滚。

生成器从真实原值推导 NULL→1 或原值+1，按目标精确数值类型检查溢出和精度；不试写。IN 候选逐键核查并合并完整断言，所有最终 SQL 保留原模板展开结果。无条件顶层 foreach 的自动 DML 种子只取非空集合，显式空/null 集合仍走输入拒绝路径；有条件保护的集合分支不改变。

候选只允许把原模板参数绑定为现有清单形式，保留已支持的固定整数和附加条件，不把源 SQL 中未支持的表达式或逻辑删除转换为另一条简化写入以绕过限制。新增回查属于用例证据，不改变原 DML 的业务语义。

无法确认字段映射、键占用、约束、前后预期或回查范围时不生成可执行用例。函数、其他表达式、多表修改、其他批量写入及超出当前验证器子集的 XML DML 记录为未支持，不能为了增加覆盖将原 SQL 改写为另一种简单写入。未知默认值和触发器等影响也不能凭源侧样本猜测。

源侧采样记录只能说明生成时的前置状态；目标侧可能缺失或不同，INSERT 新键也可能已被占用。实际执行前的两侧前置检查、环境预检、回滚及恢复判定仍由验证器负责。数据在生成后改变时需重新核对或生成，不能自动调整预期掩盖差异。

## 六、覆盖报告与设计约束

生成报告按定义、表、操作类别和来源统计：发现定义数、合并重复定义数、不同结构数、目标/有效/未生成场景数、分支覆盖、参数来源和缺口。每个输入定义都必须有生成、合并、配置排除、配额未入选或失败记录；定义可同时关联有效用例与未覆盖路径。

生成状态、采样命中情况、两库执行状态及比较结论分别记录。生成器的结构或数据覆盖不得冒充实际执行覆盖；通过执行 ID 关联验证器报告，补充实际执行、非空结果、比较行数与 DML 恢复结果。

| 设计项 | 约束 |
| --- | --- |
| 项目独立性 | 从已有提取结果与外部配置独立运行；无需修改业务项目、提取器、验证器及现有契约；生成阶段仅进行只读数据库访问 |
| JAR 依赖复用 | 独立项目可使用固定版本的契约 JAR 及其运行时依赖完成模型复用、清单读取和格式校验；不依赖提取器或验证器实现 JAR，生成业务与序列化逻辑位于生成器项目 |
| 输入缺口 | 缺失类型、映射、模板依赖或不支持转换有逐定义诊断；不从展示 SQL 猜测参数，不伪造可执行用例 |
| 输入充分性与资料一致性 | 仅问号 SQL、XML 无变体/缺依赖等均按第二节判定；最少补充资料明确，旧路径、类型/模板版本冲突不静默替换，不要求提取器新增字段 |
| 有效定义与独立通道 | 同名来源及 databaseId 选择明确，两库复用同一源侧定义；selectKey/Java 片段有独立记录；只查询或禁用某类 DML 时不受无关生成分支阻塞 |
| 契约兼容 | 查询与 DML 分别通过现有读取和格式校验；ID 唯一，参数顺序、类型、显式 null、精度及编码正确；不添加未知字段 |
| 默认数量 | 足够候选和数据下，同表跨多个简单 Mapper 合计 INSERT/UPDATE/DELETE/SELECT 各 3 条，且为不同有效用例，不随 Mapper 数量倍增 |
| 数量配置 | 四种操作类别分别设置数量，所有表统一使用；0 表示禁用，非法数量在采样前拒绝 |
| 去重与不足 | 相同结构合并来源、不同结构保留区别；样本不足及超配额结构有数量和原因，不能用重复或无效用例凑满 |
| 可重复生成 | 固定输入、配置和采样数据得到相同条目集合与 ID；合并后来源和条件路径仍可追溯，重放不重新随机采样 |
| XML 场景 | 代表性场景包含 if/choose、foreach/bind、关联、分页、聚合、空值与边界；基准参数保留，变体互不污染；超过 3 条的有效 XML 场景不会被简单配额裁剪 |
| XML 缺口 | 人工上限记录正常截断；缺失依赖、复杂表达式、动态片段及不支持类型记录真实缺口；有限输入未观察的路径不能宣称不可达或已覆盖 |
| DML 生成 | 三种用例均具备完整参数、定位键、回查及前后断言；缺失记录、键冲突或无法推导预期明确报缺口；复杂写入不改写、不试写 |
| 下游职责 | 清单交给独立验证器执行；生成器不替代双侧环境预检、比较范围判定及回滚恢复确认，失败和无法判定不得计为通过 |

## 七、功能职责与处理流程设计

### 功能职责划分

以下为生成器内部的职责边界，不是开发任务或实施顺序。定义、模板计划、样本和候选用例属于内部数据，公共产物保持第二节约定的三份文件。

| 职责 | 输入与输出关系 | 核心约束 |
| --- | --- | --- |
| 配置与输入适配 | 配置、提取文件及补充资料 → 定义目录与资料指纹 | 文件级错误在采样前发现；同名来源、databaseId、辅助语句及 Java 片段分别记录 |
| 模板与资源恢复 | 单语句模板、同版本片段 → 可求值模板计划 | 核对资源指纹与原语句匹配，明确 include 作用域，缺资料不静默替换 |
| SQL 分析与表解析 | 固定或展开后 SQL、源侧元数据 → 操作、表身份、列与参数关系 | 初步结构与最终 SQL 分开分析，不能用 XML 标签推导实际读取范围 |
| 参数依据与只读采样 | 明确参数、列关系与受控数据 → 固定类型化输入 | 单源有界采样，关联键一致；空集、预算截断与真实读库失败分别记录 |
| 场景求值与候选构造 | 模板、基准、有限输入域 → 查询或 DML 候选 | 每个场景独立；有序参数与最终 SQL 对应；DML 只读推导完整断言 |
| 去重与代表性选择 | 有效候选及数量规则 → 冻结用例集合与稳定 ID | 相同输入合并来源，兼顾数据命中和结构覆盖，数量不足不重复凑数 |
| 源侧查询探测 | 最终查询及固定参数 → 命中观察证据 | 仅只读探测；表样本命中不能代替最终查询命中，不推导双库一致性 |
| 产物与覆盖汇总 | 冻结集合及事件记录 → 清单、覆盖报告与交付状态 | 契约回读一致后才交付，清单 ID 与来源可追溯，真实缺口保留 PARTIAL |

### 数据流与依赖关系

```text
配置及提取文件 → 定义选择与资料核对
                       ↓
           固定 SQL ／ XML 模板计划
                       ↓
             SQL 分析与参数依据
                       ↓
          明确参数 ／ 单源只读采样
                       ↓
              场景求值与候选检查
                       ↓
            去重、代表性选择与冻结
                       ↓
             最终查询的源侧探测
                       ↓
           清单回读、覆盖汇总与交付
```

XML 模板计划先描述语法、片段依赖及未解析参数引用，不以完整业务类型或采样结果为前提。固定 SQL 可以直接分析；动态 XML 求值后的最终 SQL 再次分析并核对绑定，这是同一分析职责的复用，不是开发任务的反向依赖。

明确参数可以独立形成场景，自动采样按可靠列与关系依据补值。查询候选不依赖 INSERT、UPDATE、DELETE 三类候选全部成功；DML 按实际操作复用定位、约束与断言检查。选择阶段等待本轮启用的通道结束，禁用或无关通道不阻塞有效产物。

### 资源恢复与类型上下文边界

XML 资源使用明确路径与内容指纹，连接数据库前核对资料，再按 namespace、statement ID 和源侧 databaseId 匹配原始或已展开模板。include 恢复保留嵌套引用、跨资源引用、常量属性及其作用域；冲突、循环、动态片段和展开预算分别诊断。

Map/XML 基础通道与完整业务类型上下文分别管理。内置 XML 求值可以保留业务类型符号，但不能据此宣称实例化了 DTO、恢复了任意 TypeHandler 或验证了 ResultMap。完整业务类型、别名、自定义转换及复杂表达式属于扩展类型上下文；缺少可靠依据时形成缺口，不要求验证器加载业务类或放宽写入检查。

资源 SHA-256 与单语句匹配只能证明指定资料内容和已保存模板之间的关系，不能自动证明完整工程与原提取环境同版本。

### 生成状态与交付一致性

| 情况 | 状态与处理规则 |
| --- | --- |
| 在本轮规则和预算内处理完成 | COMPLETE；仅表示生成阶段正常完成，不表示条件穷尽或双库验证通过 |
| 人工探索、参数域、候选数、总数量、读取次数、样本体积或明确查询超时预算达到上限 | 记录正常截断、实际数量及未观察范围，不单独导致 PARTIAL |
| 简单用例未达到配置数量或候选因数量上限未入选 | 记录目标与实际数量、配额不足或排除原因，不重复凑数，不单独导致 PARTIAL |
| 参数、类型、模板、SQL、约束及真实采样错误，或非预算原因无有效样本 | PARTIAL；可保存其他有效用例，但真实缺口不能被数量达标掩盖 |
| 配置、输入文件、连接、契约回读、写盘等全局故障 | 运行失败，不能发布本轮成功交付标记 |

正常截断对应 STRUCTURE_LIMIT、DOMAIN_LIMIT、ATTEMPT_LIMIT、SCENARIO_LIMIT、GLOBAL_LIMIT、QUERY_CANDIDATE_LIMIT、DML_CANDIDATE_LIMIT、READ_QUERY_LIMIT、SAMPLE_BYTES_LIMIT、QUERY_TIMEOUT_LIMIT、QUOTA_SHORTFALL。实际 SQL 或读库异常不能根据错误消息被猜测成预算信号。

预算使读取中断时，丢弃不完整字段、行及回查，不能当作空数据或有效写入断言。源侧最终查询观察因预算未完成时记为 LIMITED，与真实失败或未支持结构分别记录。

两份清单经契约回读后，条目数、ID、参数与冻结集合必须一致；覆盖报告中的导出映射必须引用已交付条目。只因预算截断产生空清单可以为 COMPLETE，但没有可验证输入，下游跳过空批次，整轮不能表示数据库通过；真实空输入或非预算原因无有效用例保留 PARTIAL。

统一入口遇到 PARTIAL 默认暂停；明确接受缺口后可以继续验证有效清单，整轮仍保留未完整完成状态。入口不修改生成结论，默认按两库数据基线一致进行比较，具体策略与退出码见统一入口说明。

## 八、扩展设计边界

以下能力需独立确定资料、接口与结论范围，不由基础生成流程的完成状态推导。

### 运行 SQL 补充

运行捕获的设计方向是在指定环境中靠近 JDBC 位置取得最终 SQL 和绑定参数，补充业务 Wrapper、动态拼接、分页/count、动态表名和租户/权限插件改写，并关联 Mapper 或接口来源。采集方式及接入范围另行设计，不改变本项目基础范围不修改业务项目的边界。

捕获结果经生成器适配为现有清单格式，不能重放的对象或语法保留诊断。静态定义和运行路径共同维护覆盖记录，运行过部分接口不能证明全部定义覆盖。

### Mapper 与 API 返回映射

阶段二比较 JDBC 结果；应用层覆盖关注实际 Mapper 返回对象中的 ResultMap、TypeHandler 读取、枚举、嵌套映射和分页对象，以及业务 API 输出。这是应用层专项，不加入生成器基础范围职责，也不要求现有验证器加载 MyBatis 或业务类。

### 风险优先级与其他专项边界

关键词与高风险规则按目标数据库和实际驱动维护，仅用于验证优先级；兼容性仍以实际执行证据为准。提交行为、复杂业务事务和正式性能验证属于独立设计范围，生成与执行的观察耗时不能视为性能结论。

设计变更同步维护本阶段的边界、契约和决策；具体实现支持范围及配置示例归属工具说明，运行证据归属工具产物，不在本文记录开发进度或执行结果。

### 明确无效的动态 SQL 结构

模板分支求值、固定提取结构及最终候选在读取样本或导出前检查空 `IN`、缺失集合、悬空 `AND/OR` 和空条件括号。命中的结构按 `INVALID_SQL_STRUCTURE` 诊断记录为覆盖缺口，写入独立 `invalid-queries.json` 及覆盖信息中的 `invalidQueries`，保留原 SQL、来源和原因，阻止进入执行清单。它与源侧成功确认零行的 `NO_EXECUTION_REQUIRED` 分开处理。有效集合继续使用真实单值或多值采样并绑定原模板；不通过拼入占位常量、删除条件或改写 SQL 修补错误分支。检查只处理可确认的缺失操作数，不把未知方言解析失败等同于结构无效。
